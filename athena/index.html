Why

Agents got fast. Keeping track of them didn't.

Run three coding agents and you get three terminals, three branches, and questions scrolling by where you can't see them. Athena Studio gives the team one place to work, and you one place to look.

Agents in separate terminals

  • You flip between windows to see who is done and who is stuck.
  • A question waits in the scrollback until you happen to look.
  • Branches, plans and pull requests live in your head.
  • Close the terminal and the session goes with it.

With Athena Studio

  • Every agent in its own pane, grouped by repository, with a live monitor underneath.
  • Every question and decision in one Work list, and a red dot in the menu bar.
  • Each task gets a written plan, its own branch and a pull request you can open from the pane.
  • Close the app and agents keep running. Reopen to the same tabs and layout.
A day with Athena

One request, from plain words to a merged pull request.

A real session in our demo project: a small online shop with web, api and mobile repositories. Every picture below is the actual app.

1Ask→ 2Plan and delegate→ 3You decide→ 4Build and verify→ 5Review and merge→ 6Learn
01 · You ask

Say what you want, in plain words.

You talk to Athena, the team lead, in the athena workspace. No ticket template, no prompt engineering.

Customers keep abandoning carts. Add a saved-cart reminder on web, and paginate order history in api so mobile can use it too.
02 · Plan and delegate

Athena splits it up and hands it out.

Two plans, api first because web and mobile depend on the new response. Each goes to the agent for that repository, on its own branch and worktree, so nobody steps on anybody.

  • api-be on feat/orders-pagination
  • web-fe on feat/cart-reminder
  • The agent monitor follows both, tool call by tool call.
03 · You decide

Questions come to you. You don't go looking for them.

api-be needs one product call: 20 or 50 orders per page. Instead of waiting in a terminal you'll never scroll to, the question lands in Work and lights up the menu bar. Pick an answer, add a note if you like, and the agent carries on.

04 · Build and verify

Read the change right next to the work.

web-fe writes the banner and its tests, runs them and lints before it calls anything done. You open the changed files in Explorer and read the diff beside the terminal.

  • Tests and checks run before every pull request
  • Changed files marked M · U · A · D in the file tree
  • Syntax-highlighted diffs with line numbers
05 · Review and merge

Reviews run themselves. Merges follow your rules.

As soon as work is pushed, an automatic review starts. Comments go back to the agent until the pull request is approved. Then it merges, or waits for your click. You set that per repository.

  • Off by default, switched on per repository
  • “Confirm before merging” keeps one last click for you
  • With Codex installed, it reviews alongside Claude
06 · Learn

Tomorrow's task starts smarter.

What the team learned along the way, from review comments to QA findings, is saved as learning notes for that repository. The next task reads them before it starts.

Learning · api
+ List endpoints use cursor pagination on createdAt, 20 per page.
+ Response shape: { items, nextCursor }. Mobile reads the same shape.
→ read by the next task in api

Data and security

Your code stays on your Mac.

Athena Studio runs on your computer with tools you already trust. Here's exactly what goes where.

Runs on your MacAgents, terminals and the worklist run locally. The app does not send your code or files to novum's servers.
Your own AI accountAgents run as the Claude Code or Codex you already signed into, under that provider's terms and your plan.
Branches, not your mainEach agent works on its own branch and worktree. Automatic merge is off until you turn it on for a repository.
Signed and notarizedRelease builds are signed with an Apple Developer ID and notarized by Apple, so macOS opens them without a warning.
A separate browserThe side browser is sandboxed, opens only http and https, and keeps its sign-ins apart from your main browser.
Optional means optionalExtras that send data elsewhere only switch on when you add your own key. Without one, nothing is sent.

FAQ

Questions

Can I use Athena Studio now?

Not yet. The first public build for macOS is almost ready. Get notified and we'll email you when it's out.

How much does it cost?

Athena Studio is free to download and use. Your agents run on your own Claude Code or Codex plan, so their usage is billed by that provider as usual.

Do I need Claude Code or Codex?

Yes, at least one of them, signed in on your Mac. With Claude Code alone you get the full team. Add Codex and pull request reviews get a second opinion from a different model.

Do I need to install Athena separately?

No. The app brings the Athena core with it and sets it up on first launch.

Does my code leave my Mac?

Not to us. Athena Studio does not send your code or files to novum's servers. Your agents talk to their own provider (Anthropic or OpenAI) as they normally do, and pushes go to your GitHub.

Will agents merge code on their own?

Only if you turn it on. Automatic merge is off by default and set per repository, and you can keep a final click before every merge.

Do agents keep working when I close the app?

Yes. Terminals and agents keep running in the background. Even after you quit, open the app again and you're back to the same tabs and layout.

Can I use it for more than one company or project?

Yes. Make a pack for each: its repositories, agents and rules. Switching packs doesn't stop work in the other one, and you can export a pack for your team.

What about Windows or Linux?

Athena Studio is a Mac app for now.
