A tour of Athena Studio

What each part of the app does. For step-by-step use, see the Docs.

Workspaces

Every repository gets its own workspace.

The left side lists your repositories with the branches and agents working in them. The middle holds tabs and split terminals, with each agent in its own named pane. Explorer sits on the right.

  • A tab for each task, split into panes inside
  • Agent panes are named by agent and branch, Athena's by the task it's planning
  • Close the window and everything keeps running; reopen to the same tabs and layout
  • A new task goes to an idle agent pane for the same repository; otherwise the agent takes the largest pane, split along its longer side
  • Drag files or folders from Finder onto a pane to paste their paths into its input line; nothing is sent until you press Enter
  • Drag the edges to resize the workspace list, Explorer and monitor
  • Drag a pane's title bar onto another pane in the same tab to move it; the pane keeps running and the new layout stays after a restart
  • Give repositories a display name and image, shared with your team through the pack
How agents work

The rules every agent follows, from request to merge.

Routing and an agent per repository

The pack's routing table maps each repository to its agent. Athena uses it to split a request, and each agent reads its repository's rules, structure and notes before it starts. Work that crosses repositories goes in order, shared packages and the backend first; independent work runs at the same time.

A plan for every change

Nothing changes without a plan file. A short plan is enough when your request already says what to do. When something is yours to decide, or several repositories must line up, Athena writes a full plan with a decision console and waits for you to confirm. Each plan keeps a checkpoint, so a new session picks up where the last one stopped.

A git worktree for each task

Before an agent starts, Athena creates a new branch from your base branch in its own worktree: a separate working folder for that task. Your main checkout and its uncommitted changes stay as they are, even when the repository is messy, and several tasks run side by side.

Worklist

Press ⌘2 to open the Worklist in your browser: issues to fix, each with a Start button, learning, metrics and the archive. Metrics shows average and median times for tasks, pull requests, reviews and checks. When a plan's pull requests merge, the Worklist marks it done, and finished work moves to the archive. It has a dark and a light mode.

Checks once, at the end

While working, agents check only the parts they changed. The full verification runs once when the work is committed, and a check that didn't run is never reported as passed. A repository can hand that run to GitHub Actions: verify, merge into the base branch and deploy, with any failure sent back to the agent that did the work.

Guard hooks

Agent sessions run with hooks that block a direct git commit, push, gh pr create and git add -A. Commits and pushes go only through Athena's scripts, which stage only the files named. A secret guard also stops the common ways of printing tokens and keys.

Progress and questions

See what every agent is doing, and what it needs from you.

Agent monitor

A live feed at the bottom of the window follows each agent tool by tool: files read and edited, commands run, and what it says along the way. It works across every workspace.

  • Chips for the agents working right now, with their tool count and last activity. Click a chip to show only that agent's lines; click it again to show all.
  • One line per step: time, [agent · branch], the tool, and the file or command it touched.
  • 💬 lines are what the agent says along the way. Each agent's name keeps the color of its workspace.
  • Fold or unfold the monitor. Drag its top edge to resize, or double-click it for the default height.

Work

When an agent needs you, its question or decision goes to the top of Work, above the tasks in progress and the ones that finished in the last day. Answer it there and the agent picks up where it stopped.

Athena can also watch a repository's open GitHub issues: when turned on, new issues are imported as work items and handed to Athena, and the agent monitor shows a line for each.

Permission prompts show up in Work too, with a shortcut back to the pane. Codex approval requests for commands, file changes, extra permissions and choice-style questions can be answered right there, with their original choices and scope. Codex Browser permission prompts and startup trust dialogs are announced in Work and the menu bar.

  • Waiting for you: questions and decisions, with how long each has waited. Click one to answer it right here.
  • In progress: one line per plan with the reason it's blocked, or its status note or next step, and progress such as 3/5.
  • State: Waiting on you, Working, Blocked or Idle. Click a task to see why, decisions, progress, checks, results and next, and open its plan, decision console or pane from there.
  • Recently finished: up to five tasks done in the last 24 hours.
  • Opens the Worklist pages: Issues, Learning, Metrics and Archive.

Pane details

Open details from an agent's title bar and a panel slides in over the window, without resizing your terminals. It shows what the agent needs from you, what blocks it, its plan and its pull request.

  • For you comes first: requests to answer (click one to answer it) and the plan's blocked note.
  • At a glance: state, how long, when it started, tokens (cache shown apart), what it's doing now, the next step and the PR link.
  • Findings · result: the agent's last report, as it appears on screen. Long text folds, with More to expand it.
  • PR · auto review: pull request links and automatic review results.
  • Plan: request, progress (✓ done, ○ to do), next and checks. Click the title to open the plan. While open, the panel refreshes every 3 seconds.

Menu bar

Athena Studio has an owl icon in the Mac menu bar. A red dot on it means a question is open or a plan is blocked. Click the owl to see each agent and its status, a mountain graph of the hours agents worked over the last 3 days (today, yesterday and the day before), and token usage for the last 7 days as daily bars. While agents are working, the owl's eyes glow green.

  • Agents: working and idle counts, and one row per agent with its [pane]branch and state. Click a row to jump to that pane.
  • Work time · 3 days: the front mountain is today, the ones behind are yesterday and the day before. Height is how much agents worked in each 10-minute slot; the right side shows today's total.
  • Usage: Claude and Codex use for each window, such as 5 hours and weekly, with the reset time. The percentage turns red at 80% or more.
  • Tokens · last 7 days: one bar per day, Claude below and Codex on top, with today's and the 7-day total.
  • ☰ menu: open Athena, open the Worklist, pause notifications (for 1 hour or until 9 AM tomorrow), or quit.
Decisions and code

Make the calls, then read the code.

A decision console for plans with several choices.

When a plan has several decisions to make, Athena writes them up as a decision console: each choice with its trade-offs and a recommendation. It opens in the side browser next to the agent, and the agent continues once you've chosen.

  • Required and optional decisions, with recommended options marked
  • Side browser (⌘⇧B) for plans, consoles and your local test pages
  • Its own sign-ins, sandboxed, http and https only
  • Ask for /diagram ($diagram in Codex) to draw a service as diagrams: overall structure, user flow and affected files. Click a box to open its details

Read the work beside the terminal.

Browse the files and git changes of the current workspace and open them next to the terminal. Changed files open as a diff.

  • File tree with git status (M · U · A · D · R) and a list of changes
  • Syntax highlighting, line numbers and images
  • Reads only inside the workspace folder; Esc closes the viewer
Review and learning

Pull requests get reviewed, and the lessons stay.

Automatic PR review

In a repository with automatic review on, a single-repository PR is reviewed as soon as the agent pushes. Comments go back to the agent for up to three rounds, then the PR moves to the merge step. Big diffs are reviewed code-first, and earlier approvals carry over.

  • Off by default; in Settings, choose per repository Auto PR, Auto review and how to merge
  • Merge can be Auto, Confirm (asks you in Work) or Manual (left to you)
  • Choose the model for each role, from agents to reviewers
  • Review results and merges are recorded on the plan and the pull request
  • Claude and Codex review side by side and both must approve; without Codex, Claude reviews twice with different models, and without Claude, Codex does. Small PRs get one quick review
  • When Claude hits its usage limit, reviews switch to Codex, and each review records which engine made it. Codex reviewers run in a sandbox that can only write review results, not the code under review
  • Turn Auto PR off to skip the pull request; the work branch merges straight into the base branch, following your Merge setting. A wide change (5 or more code files, 150 or more lines, or sensitive paths) still gets an automatic review before the merge, unless Merge is Manual

Notes you choose, for the next task.

After a merge, the learning review reads the plan, the conversation and the merged changes with their review comments, and suggests notes. Only the ones you pick in Learning are kept for that repository, and agents read them at the start of the next task.

Packs and languages

One pack per company, in the language you work in.

A pack for each company you work with.

A pack holds one company's repositories, agents and routing rules. Each pack runs on its own, so switching never stops work in another.

  • Create a pack from the repositories on your Mac, or import one from a file, folder or git repository
  • Switch in one click; agents in the other pack keep working where you left them
  • Export with your work, including agent conversations and unfinished branches, and restore it later

Pick the app and agent language.

Choose English, Korean, Japanese or Chinese from the View menu. The app switches, and so do your agents: their replies, plans, issues, learning notes and commit messages.
