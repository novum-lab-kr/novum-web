A day with Athena

One request, from start to merged pull request.

A real session in our demo project: a small online shop with web, api and mobile repositories. Every picture below is the actual app.

1Ask→ 2Plan and delegate→ 3You decide→ 4Build and verify→ 5Review and merge→ 6Learn
01 · You ask

Describe the change in plain words.

In the athena workspace, describe the change and the repositories it touches. Athena, the team lead, reads it and writes the plans.

Customers keep abandoning carts. Add a saved-cart reminder on web, and paginate order history in api so mobile can use it too.
02 · Plan and delegate

Athena splits the work and hands it out.

Two plans, api first because web and mobile depend on the new response. Each goes to the agent for that repository, on its own branch and worktree.

  • api-be on feat/orders-pagination
  • web-fe on feat/cart-reminder
  • The agent monitor follows both, tool call by tool call.
03 · You decide

Questions wait for you in Work.

api-be needs one product decision: 20 or 50 orders per page. The question appears in Work and a red dot shows on the menu bar icon. Pick an answer, add a note if you like, and the agent continues.

04 · Build and verify

Check the diff before anything merges.

web-fe writes the banner and its tests, runs them and lints before it calls anything done. You open the changed files in Explorer and read the diff beside the terminal.

  • Tests and checks run before every pull request
  • Changed files marked M · U · A · D in the file tree
  • Syntax-highlighted diffs with line numbers
05 · Review and merge

Automatic review, if you turn it on.

In a repository with automatic review on, a single-repository PR is reviewed as soon as the agent pushes. Comments go back to the agent for up to three rounds. By default the merge waits for your click.

  • Off by default, switched on per repository
  • “Confirm before merging” keeps the last click for you
  • With Codex installed, it reviews alongside Claude
06 · Learn

Notes you choose, for the next task.

After a merge, the learning review suggests notes from what came up along the way, such as review comments and QA findings. Only the ones you pick in Learning are kept for that repository, and agents read them at the start of the next task.

Suggested by the learning review · picked by you
+ List endpoints use cursor pagination on createdAt, 20 per page.
+ Response shape: { items, nextCursor }. Mobile reads the same shape.

Workspaces

One workspace for each repository.

The left side lists your repositories with the branches and agents working in them. The middle holds tabs and split terminals, with each agent in its own named pane. Explorer sits on the right.

  • A tab for each task, split into panes inside
  • Agent panes are named by agent and branch, Athena's by the task it's planning
  • Close the window and everything keeps running; reopen to the same tabs and layout
  • Give repositories a display name and image, shared with your team through the pack
Split panes

Put your agents side by side.

Split a tab into panes and keep the team lead and the agents it hands work to in view at the same time. Arrange them the way you like, and the layout stays.

  • ⌘D splits right, ⌘⇧D splits down
  • ⌘⌥ and an arrow key move between panes
  • Drag a border to resize; double-click it to even them out
  • Close the window and the layout stays as it was
  • Call an agent and it takes the largest pane, split along its longer side (from the next update)
Agent monitor

Follow every agent without opening each terminal.

A live feed at the bottom of the window follows each agent tool by tool: files read and edited, commands run, and what it says along the way. It works across every workspace.

  • Only agents that are working right now show up as chips
  • Each line is labeled with the repository and branch
  • Fold it away when you need the room
Work

Agent questions land in one list.

When an agent needs you, its question or decision goes to the top of Work, above the tasks in progress and the ones that finished in the last day. Answer it there and the agent picks up where it stopped.

  • Waiting for you, in progress and recently finished in one pop-up
  • Each task shows its state: waiting on you, blocked, working or idle
  • Choices come with a recommendation and room for a note
  • QA, learning notes and the archive open from the same pop-up
Pane details

Details for one agent, opened from its pane.

Open details from an agent's title bar and a panel slides in over the window, without resizing your terminals. It shows what the agent needs from you, what blocks it, its plan and its pull request.

  • Blockers in red, questions for you at the top
  • The plan's request, progress, next step and checks
  • Running time and token usage
  • A link to the pull request and its automatic review
Decision console

A decision console for plans with several choices.

When a plan has several decisions to make, Athena writes them up as a decision console: each choice with its trade-offs and a recommendation. It opens in the side browser next to the agent, and the agent continues once you've chosen.

  • Required and optional decisions, with recommended options marked
  • Side browser (⌘⇧B) for plans, consoles and your local test pages
  • Its own sign-ins, sandboxed, http and https only
Explorer

Read the work beside the terminal.

Browse the files and git changes of the current workspace and open them next to the terminal. Changed files open as a diff.

  • File tree with git status (M · U · A · D · R) and a list of changes
  • Syntax highlighting, line numbers and images
  • Reads only inside the workspace folder; Esc closes the viewer
Automatic PR review

Automatic PR review

In a repository with automatic review on, a single-repository PR is reviewed as soon as the agent pushes. Comments go back to the agent for up to three rounds, then the PR moves to the merge step. Big diffs are reviewed code-first, and earlier approvals carry over.

  • Off by default, switched on per repository in Settings
  • Keep “Confirm before merging” on for one last click from you
  • Choose the model for each role, from agents to reviewers
  • Review results and merges are recorded on the plan and the pull request
Menu bar

A red dot when an agent needs you.

Athena Studio has an owl icon in the Mac menu bar. A red dot on it means a question is open or a plan is blocked. Click the owl to see each agent and its status.

  • Items that need you, each linked to where you answer
  • Every agent by workspace: waiting for input, working or idle
  • Claude and Codex usage with reset times, and a count of work by stage
  • Notifications only for things you need to answer, with a pause button
Packs

A pack for each company you work with.

A pack holds one company's repositories, agents and routing rules. Each pack runs on its own, so switching never stops work in another.

  • Create a pack from the repositories on your Mac, or import one from a file, folder or git repository
  • Switch in one click; agents in the other pack keep working where you left them
  • Export with your work, including agent conversations and unfinished branches, and restore it later
Languages

Pick the app and agent language.

Choose English, Korean, Japanese or Chinese from the View menu. The app switches, and so do your agents: their replies, plans, issues, learning notes and commit messages.
