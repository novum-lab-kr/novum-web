Features

Built for working with a team of agents.

Athena does the work. Athena Studio is where you watch it, steer it and sign off on it.

How the work moves

From your request to a merged pull request.

Athena, the team lead, plans and delegates. An agent for each repository builds, verifies and opens a pull request. Review, fixes and merge follow automatically, with you deciding where it counts. What the team learns is saved for the next task.

Workspaces

One workspace for each repository.

The left side lists your repositories with their branch and the agents working in them. The middle holds tabs and split terminals.

  • Tabs and split panes with keyboard shortcuts (⌘T, ⌘D, ⌘⇧D)
  • Each agent works in its own pane, named after the agent and branch
  • Close the app and everything keeps running; reopen to the same tabs and layout
  • Give repositories a display name and image for your team

Agent monitor

See what every agent is doing.

  • Only agents that are working right now show up as chips
  • Click a chip to follow one agent
  • Fold it away when you need the room

Requests

Answer your agents without leaving the app.

When an agent needs you, its question or decision lands in one list next to the work in progress and what finished recently.

  • Waiting for you, in progress, and recently done in one pop-up
  • Reply in the app; your answer goes straight to that agent
  • Open a plan or the decision console for bigger calls
  • Pane details show what an agent is doing, what blocks it, its pull request and token usage

Automatic PR review

Reviews and fixes run on their own.

As soon as an agent pushes, a review starts. Comments go back to the agent to fix, and the loop repeats until the pull request is ready.

  • Off by default and turned on per repository in Settings
  • Keep one click from you before each merge, or let it merge once reviews approve
  • Review results and merges are recorded on the plan and the pull request

Menu bar

Know when you're needed.

Athena Studio lives in the Mac menu bar. A red dot means a question or a blocked plan is waiting for you.

  • Agents by workspace: waiting for input, working or idle
  • Usage for each window with its reset time
  • Notifications only for things you need to answer, and a pause button

Explorer and side browser

Read the work beside the terminal.

Browse files and git changes for the current workspace and open them next to the terminal. A browser drawer keeps plans and test pages one shortcut away.

  • File tree with git status, and a list of changes
  • Syntax-highlighted files and diffs with line numbers
  • Side browser (⌘⇧B) for plans, the decision console and localhost pages

Packs

Set up a company once, share it everywhere.

A pack is one company's repositories, agents and routing rules. Each pack runs on its own, so switching never stops work in another.

  • Create, import and export packs from a single menu
  • Back up a pack with your work and restore agent sessions later
  • Choose a model for each role, from agents to reviewers
