작업 공간

레포마다 따로 있는 작업 공간

왼쪽에는 레포와, 그 안에서 일하는 브랜치 · 에이전트가 있습니다. 가운데는 탭과 분할 터미널이고, 에이전트마다 이름 붙은 자기 pane이 있습니다. 오른쪽은 Explorer입니다.

  • 작업마다 탭, 탭 안은 pane으로 나눕니다
  • 에이전트 pane은 에이전트 · 브랜치 이름, Athena pane은 계획 중인 일 이름
  • 창을 닫아도 모두 계속 돌고, 다시 열면 같은 탭 · 같은 배치
  • 같은 레포에서 쉬는 에이전트 pane이 있으면 새 pane 대신 그 pane으로 이어 보내고, 없으면 가장 큰 pane을 긴 쪽으로 나눠 자리를 잡습니다
  • Finder에서 파일이나 폴더를 pane에 끌어다 놓으면 경로가 입력줄에 붙습니다. Enter를 누르기 전에는 아무것도 보내지 않습니다
  • 가장자리를 끌어 왼쪽 작업 공간 목록 · 오른쪽 Explorer · 아래 모니터의 크기를 바꿉니다
  • pane 머리줄을 같은 탭의 다른 pane 위로 끌어 옮기기. pane은 계속 돌고, 바뀐 배치는 다시 켜도 남습니다
  • 레포에 보여 줄 이름과 이미지를 붙이고, 팩으로 팀과 나눕니다
에이전트가 일하는 방식

요청부터 머지까지, 모든 에이전트가 지키는 규칙.

라우팅과 레포마다 담당 에이전트

팩의 라우팅 표가 레포마다 담당 에이전트를 정합니다. Athena는 이 표로 요청을 나누고, 에이전트는 시작하기 전에 자기 레포의 규칙 · 구조 · 노트를 읽습니다. 레포를 넘는 일은 공유 패키지와 백엔드부터 차례로, 서로 상관없는 일은 동시에 돌립니다.

모든 변경에 계획서

계획서 없이는 아무것도 바꾸지 않습니다. 요청에 할 일이 이미 다 있으면 짧은 계획서로 충분합니다. 내가 정할 것이 있거나 여러 레포를 맞춰야 하면 Athena가 결정 콘솔이 딸린 정식 계획서를 쓰고 내가 확정할 때까지 기다립니다. 계획서마다 체크포인트가 있어서 새 세션이 멈춘 자리부터 이어 갑니다.

작업마다 git 워크트리

에이전트가 시작하기 전에 Athena가 기준 브랜치에서 새 브랜치를 따서 그 작업만의 워크트리, 곧 따로 떼어 낸 작업 폴더에 엽니다. 메인 체크아웃과 커밋 안 한 변경은 레포가 어수선해도 그대로 남고, 여러 작업이 나란히 돌아갑니다.

현황판

⌘2를 누르면 브라우저에 현황판이 열립니다. 해결할 이슈(이슈마다 시작 버튼) · 학습 · 지표 · 아카이브가 있고, 지표에서는 작업 · PR · 리뷰 · 검증에 걸린 평균과 중앙값 시간을 봅니다. 계획서의 PR이 머지되면 현황판이 그 계획서를 완료로 옮기고, 끝난 일은 아카이브로 갑니다. 다크 · 라이트 모드가 있습니다.

검증은 끝에 한 번

일하는 동안 에이전트는 고친 부분만 확인합니다. 전체 검증은 작업을 커밋할 때 한 번 돌고, 돌지 않은 검증을 통과했다고 보고하지 않습니다. 레포마다 이 검증을 GitHub Actions에 넘길 수 있습니다. 검증 → 기준 브랜치에 머지 → 배포까지 돌고, 실패하면 그 일을 한 에이전트에게 돌아갑니다.

보호 훅

에이전트 세션에는 git commit · push · gh pr create · git add -A를 직접 하지 못하게 막는 훅이 걸려 있습니다. 커밋과 push는 지정한 파일만 올리는 Athena 스크립트로만 합니다. 비밀값 가드는 토큰 · 키를 출력하는 흔한 방법도 막습니다.

진행과 질문

에이전트별 진행 상황과 나에게 필요한 것

에이전트 모니터

창 아래 피드에 각 에이전트가 읽고 고친 파일, 실행한 명령, 남긴 말이 올라옵니다. 어느 작업 공간에서도 보입니다.

  • 지금 일하는 에이전트마다 칩이 붙고, 도구를 쓴 횟수와 마지막 움직임이 보입니다. 칩을 누르면 그 에이전트 줄만, 다시 누르면 전체가 보입니다.
  • 한 단계가 한 줄입니다. 시각 · [에이전트 · 브랜치] · 도구 · 다룬 파일이나 명령 순입니다.
  • 💬 줄은 에이전트가 중간에 남긴 말입니다. 에이전트 이름은 그 작업 공간과 같은 색입니다.
  • 모니터를 접고 폅니다. 위쪽 가장자리를 끌어 높이를 바꾸고, 두 번 누르면 기본 높이로 돌아갑니다.

작업

에이전트가 나를 찾으면 그 질문이나 결정이 [작업] 맨 위에 올라옵니다. 그 아래로 진행 중인 일과 지난 하루 동안 끝난 일이 있습니다. 거기서 답하면 에이전트가 멈춘 데서 이어서 합니다.

레포의 열린 GitHub 이슈도 지켜볼 수 있습니다. 켜 두면 새 이슈가 작업으로 들어와 아테나에게 넘어가고, 에이전트 모니터에 이슈마다 한 줄이 뜹니다.

권한 확인도 [작업]에 올라오고, 그 pane으로 바로 갈 수 있습니다. Codex의 승인 요청(명령 · 파일 변경 · 추가 권한 · 선택형 질문)은 원래 선택지와 범위 그대로 [작업]에서 바로 답합니다. Codex Browser 권한창과 시작 신뢰창도 [작업]과 메뉴 막대에 알립니다.

  • 나를 기다리는 것: 질문과 결정이 기다린 시간과 함께 올라옵니다. 누르면 그 자리에서 답합니다.
  • 진행 중: 계획서마다 한 줄로 막힌 이유나 상태 메모 · 다음 할 일과 3/5 같은 진행률을 보여 줍니다.
  • 상태는 답 대기 · 작업 중 · 막힘 · 대기 가운데 하나입니다. 작업을 누르면 이유 · 정한 것 · 진행 · 검증 · 결과 · 다음이 보이고, 거기서 계획서 · 결정 콘솔 · pane 으로 갑니다.
  • 최근 완료: 지난 24시간 안에 끝난 작업을 다섯 개까지 보여 줍니다.
  • 현황판 페이지(이슈 · 학습 · 지표 · 아카이브)로 갑니다.

pane 상세

에이전트 머리 줄에서 상세를 열면, 터미널 크기는 그대로 둔 채 창 위로 패널이 나옵니다. 에이전트가 나에게 바라는 것, 막힌 것, 계획서와 PR을 보여 줍니다.

  • 맨 위는 내가 할 일입니다. 답할 요청(누르면 바로 답합니다)과 계획서의 막힘이 보입니다.
  • 한눈 요약: 상태 · 걸린 시간 · 시작 시각 · 토큰(캐시는 따로) · 지금 하는 일 · 다음 할 일 · PR 링크입니다.
  • 찾은 것 · 결과: 에이전트의 마지막 보고를 화면 글 그대로 보여 줍니다. 길면 접히고 [더 보기]로 펼칩니다.
  • PR · 자동 리뷰: PR 링크와 자동 리뷰 결과입니다.
  • 계획서: 요청 · 진행(✓ 끝남 · ○ 남음) · 다음 · 검증입니다. 제목을 누르면 계획서가 열립니다. 패널이 열려 있는 동안 3초마다 새로 읽습니다.

메뉴 막대

맥 메뉴 막대에 Athena Studio 부엉이가 있습니다. 빨간 점이 뜨면 열린 질문이나 막힌 계획이 있다는 뜻입니다. 부엉이를 누르면 에이전트마다 지금 상태와 함께, 지난 3일(오늘 · 어제 · 그저께) 에이전트가 일한 시간을 그린 산 그래프와 최근 7일 토큰 사용량 막대가 보입니다. 에이전트가 일하는 동안에는 부엉이 눈이 초록으로 빛납니다.

  • 에이전트: 작업 중 · 대기 수와 에이전트마다 한 줄([pane]브랜치 · 상태)입니다. 줄을 누르면 그 pane 으로 갑니다.
  • 일한 시간 · 3일: 앞 산이 오늘, 뒤로 어제와 그저께입니다. 높이는 10분마다 에이전트가 일한 양이고, 오른쪽에 오늘 합계가 나옵니다.
  • 사용량: Claude · Codex 의 창(5시간 · 주간 등)마다 쓴 비율과 다시 채워지는 시각입니다. 80% 이상이면 숫자가 빨개집니다.
  • 토큰 · 최근 7일: 하루 한 막대로, 아래는 Claude 위는 Codex 이고 오늘과 7일 합계가 함께 나옵니다.
  • ☰ 메뉴: Athena 열기 · 현황판 열기 · 알림 일시 중지(1시간 또는 내일 아침 9시까지) · Athena 종료.
결정과 코드

정할 건 정하고, 코드는 읽기

정할 게 여러 개일 때의 결정 콘솔

계획에 정할 게 여러 개면 Athena가 결정 콘솔로 정리합니다. 선택지마다 장단점과 추천이 붙습니다. 콘솔은 에이전트 터미널 옆 브라우저 칸에 열리고, 내가 고르면 에이전트가 이어서 일합니다.

  • 필수 · 선택 결정, 추천 선택지 표시
  • 옆 브라우저(⌘⇧B)로 계획서 · 결정 콘솔 · 로컬 테스트 화면
  • 로그인은 따로, 샌드박스, http · https만
  • /diagram(Codex는 $diagram)으로 서비스를 그림으로 그립니다. 전체 구조 · 사용자 흐름 · 수정 파일 영향 세 가지이고, 상자를 누르면 자세히 칸이 열립니다

터미널 옆에서 작업 읽기

지금 작업 공간의 파일과 git 변경을 둘러보고 터미널 옆에 엽니다. 바뀐 파일은 diff로 열립니다.

  • git 상태(M · U · A · D · R)가 붙은 파일 트리와 변경 목록
  • 문법 강조 · 줄 번호 · 이미지
  • 작업 공간 폴더 안만 읽습니다. Esc로 뷰어 닫기
리뷰와 학습

리뷰를 거치는 PR, 남는 배운 것

PR 자동 리뷰와 수정

자동 리뷰를 켠 레포에서는 에이전트가 푸시하면 그 레포 하나짜리 PR을 바로 리뷰합니다. 의견은 에이전트에게 돌아가고 최대 3라운드까지 고친 뒤 머지 단계로 넘어갑니다. 큰 diff는 코드부터 보고, 앞서 받은 승인은 이어집니다.

  • 기본은 꺼짐, 설정에서 레포마다 자동 PR · 자동 리뷰 · 머지 방식을 고릅니다
  • 머지는 자동 · 확인 후([작업]에서 묻습니다) · 직접(내가 머지) 중에서 고릅니다
  • 에이전트 · 리뷰어처럼 역할마다 모델을 고릅니다
  • 리뷰 결과와 머지는 계획서와 PR에 기록됩니다
  • Claude와 Codex가 나란히 리뷰하고 둘 다 승인해야 머지합니다. Codex가 없으면 Claude가, Claude가 없으면 Codex가 다른 모델로 두 번 봅니다. 작은 PR은 리뷰를 한 번만 빠르게 합니다
  • Claude가 사용량 한도에 걸리면 리뷰가 Codex로 넘어가고, 어느 엔진이 리뷰했는지 기록합니다. Codex 리뷰어는 리뷰 결과만 쓸 수 있는 격리 샌드박스에서 돌아 리뷰 대상 코드를 고치지 못합니다
  • 자동 PR을 끄면 PR 없이 작업 브랜치를 기준 브랜치에 바로 머지하고, 머지 설정을 그대로 따릅니다. 넓은 수정(코드 파일 5개 이상 · 150줄 이상 · 민감 경로)이면 머지 앞에 자동 리뷰가 들어갑니다. 머지가 직접이면 리뷰하지 않습니다

고른 노트만, 다음 작업으로

머지가 끝나면 학습 리뷰가 계획서 · 작업 대화 · 머지된 변경과 리뷰 의견을 읽고 노트를 제안합니다. [학습]에서 내가 고른 것만 그 레포의 학습 노트로 남고, 에이전트는 다음 작업을 시작할 때 이 노트를 읽습니다.

학습 · api
학습 리뷰가 제안 · 내가 고름
+ 목록 API는 createdAt 커서 페이지 나누기, 한 페이지 20개.
+ 응답 모양: { items, nextCursor }. mobile도 같은 모양을 읽습니다.

팩과 언어

회사마다 팩 하나, 내가 쓰는 언어로

회사마다 팩 하나씩

팩에는 한 회사의 레포 · 에이전트 · 라우팅 규칙이 들어 있습니다. 팩마다 따로 돌아서, 바꿔도 다른 팩의 일은 멈추지 않습니다.

  • 내 맥의 레포로 팩을 만들거나, 파일 · 폴더 · git 레포에서 가져옵니다
  • 팩을 바꿔도 다른 팩의 에이전트는 하던 일을 계속합니다
  • 에이전트 대화와 끝나지 않은 브랜치까지 내 작업과 함께 내보내고, 나중에 되살립니다
