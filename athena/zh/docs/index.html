安装之前

请先确认以下几项。

Athena Studio 在你的 Mac 上运行，驱动你已在用的编程智能体。

  • macOSmacOS 13 Ventura 或更高版本
  • AI 智能体Claude Code 或 Codex，用你自己的账号登录。
  • git 和 Python 3如果没有，首次启动时 macOS 会提示安装。想提前安装，可在终端运行 xcode-select --install
  • Node.jsAthena 应用使用 Node 24.22.1。
  • GitHub需要能访问你的仓库。创建拉取请求和自动审查需要 gh CLI。

首次设置前要准备的

  1. 登录智能体。 安装 Claude Code 或 Codex，并用你自己的账号登录。如果只装了一个，Athena Studio 就启动它；两者都有时，会在第一次询问用哪个并记住。在 athena 工作区中启动另一个工具，记住的选择也会随之改变。
  2. 登录 GitHub。 安装 gh CLI 并运行 gh auth login。没有它，Athena 无法创建拉取请求。
  3. 克隆你的仓库。 放在主文件夹下。Athena 会向下查找三层文件夹，所以按团队或公司文件夹归类也没问题。你不负责的仓库可以不放。
  4. 用 nvm 安装 Node，并安装包管理器。 检查会使用每个仓库 .nvmrc 中的 Node 版本，并按仓库的 lock 文件选用 npm、pnpm 或 yarn。
  5. 为每个仓库创建 .env。 按该仓库自己的说明创建。Athena 会把 .env* 文件复制到每个任务的工作树中。

安装并打开

安装 Athena Studio。

  1. 在下载页面获取适合你 Mac 芯片的 .dmg。
  2. 打开下载的文件，把 Athena Studio 拖到“应用程序”。
  3. 打开 Athena Studio。它已通过 Apple 签名和公证，打开时不会出现安全警告。如果缺少 git 或 Python 3，macOS 会提示安装 Apple 的 Command Line Tools。
  4. 首次启动时，开始画面会提供“新建包”和“导入包”。包是一家公司或一个项目的仓库、智能体和规则的集合。

什么是包

包里装着 Athena 对你的仓库所了解的一切。

Athena 本身(核心)随应用一起提供：工作流程、钩子、待办页面、学习和通用规则都在其中，它并不了解你的公司。与你的仓库有关的一切都放在包里。

包里有什么

仓库列表
每个仓库的生产分支和 PR 目标分支，以及 PR 自动审查等设置。
路由表
哪个需求交给哪个仓库和智能体、检查命令以及公司技能。
智能体
每个仓库一个负责智能体的配置。
知识
每个仓库的笔记：规则、结构、模式、工作流程和陷阱。还有公司惯例和学到的内容。
检查脚本
每个仓库一个验证脚本。
文档和归档
服务概览、公司说明文档和脚本、代码基线以及已完成的工作。
与代码分开仓库仍留在原来的文件夹中，包只是链接到它们。删除包时会先备份，仓库文件夹保持不变。
与团队共享导出包后，团队成员可以从压缩包、文件夹或 git 仓库导入。你的 Mac 上仓库所在的位置不会包含在内。
多个包每个包都有自己的 Athena 文件夹和待办页面，因此可以同时打开多个包。打开另一个包时，这个包的智能体会继续工作，包与包之间不会混在一起。

在标签栏左侧的包名称(⌘⇧P)中切换、新建、导入或导出。

首次设置

首次设置：Athena 熟悉你的仓库

创建包时，Athena 会替你完成设置。它只读取你的代码。

分步操作

  1. 点击“新建包”。 它在开始界面上，也在标签栏左侧的包菜单中。无需填写任何内容：Athena Studio 会创建一个空包及其专属的 Athena 文件夹，并把窗口切换到这个包。
  2. 等待 Athena 启动。 你选择的工具会在 athena 工作区中启动，并自动开始首次设置。要手动开始，在 Claude Code 中输入 /setup，在 Codex 中输入 $setup。Codex 第一次会询问是否信任该文件夹及其钩子。如果两者都没有安装，请安装其一，再在 athena 工作区中启动。
  3. 选择仓库。 Athena 会找出这台 Mac 上的仓库，按找到的顺序全部列在控制台中。勾选要加入的仓库(或顶部的“全部”)，然后确认。
  4. 回答几个问题。 公司名称(小写英文字母，会成为包的文件夹名)以及指代你们服务和品牌的名称。仓库的生产分支、PR 目标分支、类型或层级中推测错误的部分。智能体名称(默认是仓库名加 -fe 或 -be)。以及哪些仓库开启 PR 自动审查和合并：默认都不开启，之后可以在设置中更改。
  5. 等待 Athena 读取。 它为每个仓库配置智能体，读取每个仓库的生产分支，写下规则、结构笔记、路由表和服务概览。无法确认的内容不会去猜，而是标为“待确认”。
  6. 两个可选问题。 现在还是以后起草服务流程文档。这些文件会放进你的仓库，所以只有你开口才会提交。另一个是你是否有 TypeSafe Jev 密钥：如果有，请粘贴到打开的输入 pane 中，不要粘贴到对话里。没有也一切照常运行。
  7. 阅读报告。 Athena 会为每个仓库运行一次检查并建立代码基线，然后报告已创建的内容、检查结果以及仍需你处理的事项。
由你确认要加入的仓库、公司名称、智能体名称，以及哪些仓库开启自动审查。推测错误的地方在这里修正。
Athena 负责准备为每个仓库配好规则和笔记的智能体、路由表、服务概览和代码基线。不会修改你的仓库，安装或 fetch 前都会先询问。
完成之后Athena 会报告已完成的内容和仍需你处理的事项。然后在 athena 工作区交代第一项任务即可。
Athena 的工作步骤
  1. 在你的 Mac 上找到仓库，推测每个仓库的类型(前端或后端)、生产分支和 PR 基准分支。
  2. 向你确认要加入哪些仓库、公司名称、智能体名称以及哪些仓库开启自动审查。推测错误的地方也在这一步修正。
  3. 为每个仓库创建智能体，并配好规则、结构笔记、注意事项笔记和检查脚本。
  4. 读取每个仓库的生产分支，填写智能体负责的内容、必须遵守的规则、语言与类型状况以及简短的服务概览。决定哪个需求交给哪个仓库的路由表由 Athena 编写。
  5. 如有需要，会在每个仓库起草服务流程文档。这些文件会放进你的仓库，所以只有你开口才会提交。
  6. 先运行一次检查并建立代码基线，之后的更新只处理有变化的部分。
  7. 如果有 TypeSafe Jev 密钥，会在输入 pane 中登记，而不是在对话里。密钥只保存在这台 Mac 上。

首次设置时 Athena 不会做的事

  • 不会修改你的仓库，只读取生产分支。
  • 不会未经询问就安装任何东西。为建立代码基线而 fetch 时也会先告诉你。
  • 不会为你没选的仓库开启 PR 自动审查或合并。
  • 不会通过对话接收密钥或令牌。

第一个请求

收到报告后，留在 athena 工作区，用平常的话说出你想做的事。先试试“告诉我现状”：会列出每个仓库的分支和改动。然后交代真正的工作。之后的流程见下一节。

首次设置卡住时

找不到某个仓库
告诉 Athena 它在哪个文件夹。Athena 会在其下查找三层。
智能体没有在 pane 中打开
确认是在 Athena Studio 窗口内的 athena 工作区中启动 claude 或 codex。在普通终端中，Athena 只会告诉你该运行什么。
检查显示 ❌ 或已跳过
首次设置不会把它算作通过，而是标为“待确认”，例如依赖还没有安装时。安装前 Athena 会先询问。
出现 Node 版本警告
在该仓库的文件夹中运行 nvm use。

如果有团队给你的包，请在“文件 → 导入包…”中选择压缩包、包文件夹或 git 仓库。

第一项任务

从一个需求到合并的拉取请求。

下面的演示项目是一家有 web、api、mobile 仓库的小商店。你自己的仓库也是同样的流程。

01

向 Athena 提需求

在 athena 工作区写下要改的内容和涉及的仓库，用平常的话写就行。

顾客总是放弃购物车。在 web 上加一个已保存购物车的提醒，再把 api 的订单历史做成分页，让 mobile 也能用。
02

确认计划

Athena 为每个仓库写好计划并交给该仓库的智能体，智能体在新的 pane 中用独立分支工作。计划里有多个选择时，Athena 会在侧边浏览器中打开决策控制台供你挑选。

03

回答问题

智能体等待决定时，右上角的 [工作] 会出现圆点，问题位于 [等你处理] 下。点开选择答案，需要时附上备注后发送。菜单栏的猫头鹰也会出现红点。

04

查看进度

窗口底部的智能体监视器会显示每个智能体读取、修改和运行的内容。要看某个智能体的计划、阻塞和拉取请求，可从其 pane 标题栏打开详情。

05

检查改动

智能体在打开 draft 拉取请求前会运行测试和检查。在右侧 Explorer 中打开 [变更] 并点击文件，即可在终端旁阅读 diff。

06

合并

在开启自动 PR 的仓库中，Athena 会创建拉取请求；若同时开启自动审查，还会自动审查并修正。合并可选自动、确认后(在 [工作] 中询问你)或手动，选手动时合并会等待你点击。关闭自动 PR 的仓库不建拉取请求，按合并设置处理，选手动时则停留在工作分支。即便如此，范围较大的修改在合并前仍会自动审查。

07

保留经验

合并后，学习审查会提出笔记建议。打开待办页面(⌘2)，在 [学习] 中挑选要保留的内容。该仓库的下一项任务会读取这些笔记。

应用各部分

各功能的位置。

工作区
左侧列表中每个仓库对应一个工作区，里面有分支和智能体。中间是标签页和拆分的 pane，每个 pane 一个智能体。按 ⌘1 回到这里。
智能体监视器
位于窗口底部，只显示正在工作的智能体，可用 ⌄ 收起。
工作
标签栏右上角。等你处理的问题、进行中的工作，以及最近 24 小时完成的工作。
待办页面(⌘2)
在默认浏览器中打开：问题、学习、指标和归档。
pane 详情
智能体 pane 标题栏右侧的图标。显示计划、进度、阻塞、token 和拉取请求，按 Esc 关闭。
Explorer
右侧。当前工作区的 [文件] 和 [变更]，有改动的文件以 diff 打开。
侧边浏览器
右侧抽屉(⌘⇧B)，用于打开计划、决策控制台和本地测试页面。登录信息与常用浏览器分开保存。
菜单栏
Mac 菜单栏里的猫头鹰。红点表示有待回答的问题或受阻的计划，点击可查看每个智能体的状态。

设置

调整 Athena Studio 的设置。

PR 自动化
标签栏最右侧的 ⚙。每个仓库有“自动 PR”和“自动审查”，下方可把合并设为“自动”“确认后”或“手动”。在你开启前一直是关闭的。
语言
“显示 → 语言”。应用和智能体会一起切换，包括回复、计划、问题和提交信息。
通知
点击菜单栏的猫头鹰 → “暂停通知”，可暂停 1 小时或到次日早上 9 点。
包
标签栏左侧的包名称(⌘⇧P)：切换、新建、导入或导出。其他包的智能体会继续工作，导出时还可以包含智能体对话和未完成的分支。
仓库名称和图片
在左侧列表中右键点击仓库。名称和图片保存在包中，团队成员也能看到。

更新

让 Athena Studio 保持最新。

从 0.17.6 起，应用可以自行更新：打开设置(⚙)，有新版本时在“应用更新”一行按“更新”。应用会下载、校验并重启。若中途失败，当前版本会继续运行，并显示简短原因。

还在用 0.15.8？该版本无法自行更新。请从下载页面获取一次新的 .dmg，把 Athena Studio 拖到“应用程序”中覆盖旧版本。包和工作内容会保留，之后即可在 ⚙ 中更新。

应用自带的 Athena 核心会在你打开新版本时更新，即使智能体正在工作也没关系。更新后会弹出窗口，显示更新前后的版本、新增内容和更新结果。

数据与安全

哪些在你的 Mac 上运行，哪些会发往别处。

应用在你的电脑上运行。智能体仍会向其 AI 服务商发送请求，推送时代码会发到 GitHub。

在你的 Mac 上运行智能体、终端和待办都在本地运行。应用不会把你的代码或文件发送到 Novum Lab 的服务器。
使用你自己的 AI 账号智能体以你已登录的 Claude Code 或 Codex 身份运行，遵循该服务商的条款和你的套餐。
智能体在分支上工作每个智能体在自己的分支和工作树上工作。在你为某个仓库开启之前，自动合并一直是关闭的。
签名与公证公开发布版使用 Apple Developer ID 签名并经过 Apple 公证。
单独保存登录信息的浏览器侧边浏览器运行在沙盒中，只打开 http 和 https，登录信息与你的常用浏览器分开保存。
TypeSafe Jev 集成是可选的只有在你填入自己的 TypeSafe Jev 密钥时，才会用它检查学习建议：查看是否与已有笔记重复，并对学习审查进行判定。判定时会发送已完成任务的计划书、已合并的修改及审查意见和工作对话，像密钥的值会先被遮盖。没有密钥时不会向 Jev 发送任何内容。

故障排除

遇到问题时。

pane 断开或没有反应
“显示 → 重新连接工作窗口”。pane 和智能体保持不变。
重新连接也无效
“显示 → 重启工作窗口守护进程”。这会关闭所有打开的 pane 及其智能体。
智能体好像卡住了
看看 [工作] 中是否有等你处理的问题，以及 pane 详情里是否有阻塞。
拉取请求没有打开
确认已安装并登录 gh CLI(gh auth login)，且仓库设置了 GitHub 远程。
提示缺少 Claude Code、Codex、git 或 Python
在终端中安装并登录(git 和 Python 用 xcode-select --install)，然后重新打开 Athena Studio。
还是不行
“显示 → 重置工作室”会删除所有包和 pane 并重启应用，仓库文件夹会保留。请先反馈问题，最后再使用。

日志位于 ~/Library/Application Support/Athena Studio(daemon.log、board.log、pack.log)。反馈问题时请附上。

FAQ

常见问题

哪些 Mac 可以用？

macOS 13 Ventura 及以上的 Apple Silicon 或 Intel Mac 都可以使用，免费下载。

要花钱吗？

Athena Studio 可以免费下载和使用。智能体使用你自己的 Claude Code 或 Codex 套餐运行，用量照常由该服务商计费。

必须要有 Claude Code 或 Codex 吗？

是的，你的 Mac 上至少要登录其中一个。智能体用哪个都能运行。PR 自动审查也只需其中一个：两者都有时，Claude 和 Codex 并行审查；只有一个时，由它用不同的模型审查两次。

智能体会自己合并代码吗？

只有在你开启时才会。自动合并默认关闭，按仓库设置，你也可以在每次合并前保留最后一次点击。

关闭应用后，智能体还会继续工作吗？

会。终端和智能体在后台继续运行。即使退出了应用，重新打开后也会回到同样的标签页和布局。

可以用于多家公司或多个项目吗？

可以。为每个创建一个包：包含其仓库、智能体和规则。切换包不会中断另一个包里的工作，你还可以导出包与团队共享。

支持 Windows 或 Linux 吗？

目前 Athena Studio 只有 Mac 版。

发现问题或有建议？

请在 GitHub 提交 issue，可选择错误报告或功能建议模板。
