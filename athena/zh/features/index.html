工作区

每个仓库都有自己的工作区。

左侧列出你的仓库，以及在其中工作的分支和智能体。中间是标签页和拆分终端，每个智能体都有自己命名的 pane。右侧是 Explorer。

  • 每个任务一个标签页，标签页内可拆分 pane
  • 智能体 pane 以智能体和分支命名，Athena 的 pane 以它正在规划的任务命名
  • 关闭窗口，一切照常运行；重新打开还是同样的标签页和布局
  • 同一仓库里有空闲的智能体 pane 时，新任务直接交给它而不再新开；没有时，把最大的 pane 沿长边拆分来安放
  • 把 Finder 中的文件或文件夹拖到 pane 上，路径会粘贴到其输入行；按下 Enter 前不会发送任何内容
  • 拖动边缘可调整工作区列表、Explorer 和监视器的大小
  • 把 pane 的标题栏拖到同一标签页的另一个 pane 上即可移动；pane 会继续运行，新布局在重启后依然保留
  • 为仓库设置显示名称和图片，通过包与团队共享
从仓库到智能体

Athena 读取你的仓库，为每个仓库创建负责智能体。

读取你的仓库

首次设置时，Athena 会找到你 Mac 上的仓库，推测每个仓库的类型、生产分支和 PR 基准分支。由你确认要包含哪些仓库，猜错的地方在这里改正。它只读取生产分支，不会修改你的仓库。

每个仓库一个智能体

每个仓库都有自己的智能体，配好规则、结构笔记、注意事项笔记和检查脚本。Athena 会填写智能体负责的内容、必须遵守的规则以及语言与类型状况，并写一份简短的服务概览。

路由表

决定哪个需求交给哪个仓库的路由表由 Athena 编写。之后的需求按这张表拆分，每部分交给对应仓库的智能体。

标出来，而不是去猜

Athena 无法确认的内容会标为“待确认”。失败或被跳过的检查不算通过，而是列出来让你确认。

先问再动手

不会未经询问就安装任何东西，为建立代码基线而 fetch 时也会先告诉你。不会为你没选的仓库开启自动 PR 审查或合并，也不会通过聊天接收密钥。

检查后再报告

为每个仓库运行一次检查并建立代码基线，之后的更新只处理改动的部分。然后报告它做了什么，以及还有哪些需要你处理。

智能体如何工作

从需求到合并，每个智能体都遵守的规则。

路由与每个仓库的负责智能体

包里的路由表为每个仓库指定负责的智能体。Athena 用它拆分需求，智能体在开始前先读取自己仓库的规则、结构和笔记。跨仓库的工作按顺序进行，先共享包和后端；互不相关的工作同时进行。

每次改动都有计划书

没有计划书就不做任何改动。需求已经写清要做什么时，一份简短的计划书就够了。有需要你决定的事，或要协调多个仓库时，Athena 会写一份附带决策控制台的正式计划书，并等你确认。每份计划书都有检查点，新会话可以从上次停下的地方继续。

每项任务一个 git 工作树

智能体开始之前，Athena 会从基准分支切出新分支，并在这项任务专用的工作树(即独立的工作文件夹)里打开。即使仓库很乱，你的主检出和未提交的改动也保持原样，多项任务可以并行。

最后只验证一次

工作中，智能体只检查改动的部分。完整验证在提交时跑一次，没跑过的检查绝不报告为通过。每个仓库都可以把这次验证交给 GitHub Actions：验证 → 合并到基准分支 → 部署，失败时会退回给做这项工作的智能体。

保护钩子

智能体会话带有钩子，禁止直接执行 git commit、push、gh pr create 和 git add -A。提交和 push 只能通过 Athena 的脚本进行，脚本只处理指定的文件。密钥守卫还会拦下打印令牌和密钥的常见方式。

待办页面

按 ⌘2 在浏览器中打开待办页面。待解决的问题按仓库分组，每个问题都有开始工作按钮，旁边是学习、归档和指标标签页。计划书的 PR 合并后，待办页面会把它标为完成，做完的工作移入归档。它有深色和浅色模式，并跟随应用的语言。

学习

学习标签页汇集代理在工作中发现的陷阱作为学习候选，并按要写入的仓库笔记分批。可以逐条查看内容、修改或删除，再把勾选的整批加入。加入的内容会写进该仓库的笔记，代理在开始工作前会读取，并通过 git 与团队共享。在个人记忆中，可以只读查看 Claude 和 Codex 从对话中记住的内容。

归档

归档标签页按日期保存已完成的问题和计划书。可以按类型、仓库和负责人筛选，按标题、摘要和提交搜索，或选择年、月、日查看。每一项都显示仓库、状态和提交数，点击即可打开完整记录。

指标

在指标标签页中，可以选择最近 1、7、30 天或从某个开始日期起的时段，对比上一时段查看任务、PR、审查和检查所用时间的平均值、中位数和 p75。图表显示各项工作耗时的分布、每天完成的工作、检查结果以及各阶段所用时间。

进度与问题

看到每个智能体在做什么，以及需要你做什么。

智能体监视器

窗口底部的实时动态逐个工具地跟踪每个智能体：读过和改过的文件、运行的命令，以及过程中说的话。在每个工作区都能看到。

  • 每个正在工作的智能体都有一个标签，显示用过的工具次数和最后一次动作。点击标签只看这个智能体的行，再点一次回到全部。
  • 每一步一行：时间、[智能体 · 分支]、工具，以及涉及的文件或命令。
  • 💬 行是智能体在过程中说的话。智能体名称与所在工作区的颜色相同。
  • 折叠或展开监视器。拖动上边缘可调整高度，双击恢复默认高度。

工作

智能体需要你时，问题或决定会出现在 [工作] 最上方，下面是进行中的任务和最近一天完成的任务。在那里回答后，智能体会从停下的地方继续。

还可以监视仓库中未关闭的 GitHub 议题：开启后，新议题会作为任务导入并交给 Athena，智能体监视器会为每个议题显示一行。

权限确认也会出现在 [工作] 中，并可直接跳回对应的 pane。Codex 的批准请求(命令、文件修改、额外权限和选择式问题)可以在 [工作] 中直接回答，保留原有的选项和范围。Codex Browser 的权限窗口和启动时的信任窗口也会在 [工作] 和菜单栏中提示。

  • 等你处理：问题和决定会连同已等待的时间一起列出。点击即可就地回答。
  • 进行中：每个计划一行，显示受阻原因或状态备注、下一步，以及 3/5 这样的进度。
  • 状态为 等你回复、工作中、受阻、空闲 之一。点击任务可查看原因、已定事项、进度、验证、结果和下一步，并可从那里打开计划、决策控制台或前往 pane。
  • 最近完成：最多显示最近 24 小时内完成的 5 个任务。
  • 打开待办页面（问题、学习、指标、归档）。

pane 详情

从智能体的标题栏打开详情，一个面板会从窗口上方滑出，不会改变终端的大小。它显示智能体需要你做什么、被什么卡住、它的计划和拉取请求。

  • 最上方是需要你做的事：待回答的请求（点击即可回答）和计划中的受阻说明。
  • 一览：状态、持续时间、开始时间、Token（缓存单独显示）、当前在做的事、下一步和 PR 链接。
  • 发现 · 结果：按屏幕原文显示智能体的最后一份报告。内容较长时会折叠，点 [更多] 展开。
  • PR · 自动评审：拉取请求链接和自动评审结果。
  • 计划书：请求、进度（✓ 已完成、○ 未完成）、下一步和验证。点击标题打开计划。面板打开期间每 3 秒刷新一次。

菜单栏

Mac 菜单栏里有 Athena Studio 的猫头鹰图标。出现红点表示有待回答的问题或受阻的计划。点击猫头鹰即可看到每个智能体的状态、最近 3 天（今天、昨天和前天）智能体工作时长的山形图，以及最近 7 天按天显示的 Token 用量柱状图。智能体工作期间，猫头鹰的眼睛会发出绿光。

  • 智能体：工作中和空闲的数量，以及每个智能体一行（[pane]分支和状态）。点击一行即可跳到该 pane。
  • 工作时长 · 3 天：前面的山是今天，后面是昨天和前天。高度表示每 10 分钟内智能体的工作量，右侧显示今天的合计。
  • 用量：Claude 和 Codex 在每个窗口（如 5 小时、每周）的使用比例和重置时间。达到 80% 及以上时数字变红。
  • Token · 最近 7 天：每天一根柱子，下面是 Claude，上面是 Codex，并显示今天和 7 天的合计。
  • ☰ 菜单：打开 Athena、打开待办、暂停通知（1 小时或到明天早上 9 点）、退出 Athena。
决策与代码

做出决定，再看代码。

需要做多个决定时，整理成决策控制台。

当一份计划有多个需要决定的事项时，Athena 会把它们整理成决策控制台：每个选项都附有利弊和推荐。它在智能体旁边的侧边浏览器中打开，你做出选择后，智能体就会继续。

  • 必选和可选的决定，标出推荐选项
  • 侧边浏览器（⌘⇧B）用于计划、决策控制台和本地测试页面
  • 独立的登录信息，沙盒运行，只支持 http 和 https
  • 用 /diagram(Codex 中为 $diagram)把服务画成图：整体结构、用户流程和受影响的文件。点击方框即可打开详情

在终端旁边阅读工作成果。

浏览当前工作区的文件和 git 改动，并在终端旁边打开。改动过的文件以 diff 形式打开。

  • 带 git 状态（M · U · A · D · R）的文件树和改动列表
  • 语法高亮、行号和图片
  • 只读取工作区文件夹内的内容；按 Esc 关闭查看器
审查与学习

拉取请求经过审查，经验得以保留。

PR 自动审查与修复

在开启自动审查的仓库里，智能体一推送就会审查只涉及该仓库的 PR。意见返回给智能体，最多修改 3 轮后进入合并环节。大的 diff 优先审查代码，之前的批准会保留。

  • 默认关闭，在设置中按仓库选择自动 PR、自动审查和合并方式
  • 合并可选自动、确认后(在 [工作] 中询问你)或手动(由你来合并)
  • 为每个角色选择模型，从智能体到审查者
  • 审查结果和合并都会记录在计划和拉取请求上
  • Claude 和 Codex 并行审查，两者都批准才会合并；没有 Codex 时由 Claude、没有 Claude 时由 Codex 用不同的模型审查两次。小的 PR 只快速审查一次
  • Claude 达到用量上限时，审查会切换到 Codex，并记录每次审查由哪个引擎完成。Codex 审查者在只能写入审查结果的隔离沙箱中运行，无法修改被审查的代码
  • 关闭自动 PR 后，不建拉取请求，工作分支会直接合并到基准分支，并遵循你的合并设置。若是范围较大的修改(5 个以上代码文件、150 行以上或敏感路径)，合并前仍会自动审查；合并设为手动时不审查

只把你选中的笔记带到下一项任务。

合并后，学习审查会阅读计划书、工作对话以及已合并的修改和审查意见，并提出笔记建议。只有你在 [学习] 中选中的才会保存为该仓库的学习笔记，智能体在下一项任务开始时读取。

包与语言

每家公司一个包，用你工作的语言。

每家公司一个包。

一个包包含一家公司的仓库、智能体和路由规则。每个包独立运行，切换时不会中断另一个包里的工作。

  • 用 Mac 上的仓库创建包，或从文件、文件夹或 git 仓库导入
  • 一键切换；另一个包里的智能体会在原处继续工作
  • 连同你的工作一起导出，包括智能体对话和未完成的分支，之后再恢复

选择应用和智能体的语言。

在“显示”菜单中选择英语、韩语、日语或中文。应用随之切换，智能体也一样：回复、计划、问题、学习笔记和提交信息都会跟着变。

在 Mac 上试试 Athena Studio。

适用于 macOS 13 及以上的 Apple Silicon 和 Intel Mac，免费使用。
